Portfolio Structure — 3 Approaches

All three: full professional pivot, no fake projects, Adams as easter egg only. Which skeleton fits?

A

Single scrolling page

One URL, everything flows: Hero → About → Skills → Experience (brief) → Contact. No multi-page nav. Clean, modern, mobile-first. Recruiters scroll once and have the full picture.

hrco.github.io/
├── #hero — Name + headline
├── #about — 3 sentences
├── #skills — tag grid
├── #experience — 4-line timeline
└── #contact — email + LinkedIn + IG

Pros

  • Fast to build on existing CSS
  • Zero navigation complexity
  • LinkedIn-style scan

Cons

  • Less room to expand later
  • All eggs in one scroll
B

Minimal landing + About page

Home = striking hero only (name, headline, 1 sentence, 3 buttons: About / LinkedIn / Email). About page has the full bio, skills, experience, certs. Two pages, both tight.

hrco.github.io/
├── index.html — hero only
└── about.html — full profile
    ├── Bio
    ├── Skills
    ├── Experience
    └── Contact

Pros

  • Homepage is striking, not dense
  • About page is shareable standalone
  • Easy to extend later

Cons

  • Extra click before real content
  • More pages to maintain
C

Keep existing structure, replace content

Existing site already has: index, about_me, foto, news, projects pages + solid CSS system. Strip all placeholder content, replace with real professional data. Projects page becomes "Work history" or gets hidden for now.

hrco.github.io/
├── index.html — new hero + skills
├── about_me.html — real bio
├── projects.html → "Experience"
├── foto.html — keep (photos)
└── news.html — keep (RSS)

Pros

  • Least rebuild work
  • Existing CSS/JS intact
  • News + foto already work

Cons

  • Carries legacy structure decisions
  • Projects page needs repurposing
